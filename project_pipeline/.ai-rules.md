# AI Development Rules

## Project Name

Data Pipeline Monitoring and Recovery Framework

---

# Objective

Build a modular data engineering project that demonstrates ETL pipelines,
pipeline monitoring, failure detection, recovery mechanisms, and dashboard visualization.

---

# Technology Stack

Language:
- Python 3.x

Database:
- PostgreSQL

Libraries:
- pandas
- psycopg2-binary
- requests
- streamlit
- python-dotenv

Development:
- VS Code
- Git

# Coding Standards

Always:

- Use modular programming
- Follow PEP-8
- Use descriptive variable names
- Add comments where necessary
- Use type hints whenever appropriate
- Use exception handling
- Use logging
- Never hardcode credentials

---

# Configuration

Read configuration from:

.env

Never hardcode:

- database password
- host
- API keys

---

# Database Rules

Always use:

database/db.py

Never create duplicate database connection code.

---

# Error Handling

Always use:

try

except

finally

Rollback database transactions when necessary.

---

# Monitoring Requirements

Every pipeline execution should record:

- Pipeline Name
- Source Type
- Start Time
- End Time
- Execution Duration
- Status
- Rows Processed
- Retry Count
- Error Message

---

# Recovery Rules

Retry only:

- API Timeout
- Network Failure
- Temporary Database Connection Failure

Do NOT retry:

- Missing CSV
- Invalid CSV Format
- Missing Required Columns
- Invalid Data

---

# Dashboard Requirements

Display:

- Pipeline Status
- Pipeline Health
- Execution History
- Retry Count
- Error Logs
- Data Freshness

# AI Instructions

When generating code:

- Generate only one file unless requested otherwise.
- Never rewrite unrelated files.
- Reuse existing modules whenever possible.
- Explain any new dependencies.
- Keep functions small and reusable.
- Do not introduce unnecessary complexity.

Always assume this is an MCA academic project that should remain understandable and maintainable.
